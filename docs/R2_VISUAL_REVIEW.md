## 审查范围与方法

先阅读了 `docs/R0_DATA_AUDIT.md`、`docs/R1_INPUT_PREP.md`、`docs/R2_OBSTACLE_CANDIDATES.md`。随后检查 R1 四帧默认清理结果，以及 R2 每帧 fine/coarse 两套结果的 `result.json`、`segmentation.npz`、平面/剩余/聚类 PLY 和已有三视角 PNG。此次只分析既有结果；**没有重新运行 RANSAC 或 DBSCAN**，也没有改动原始数据、R1/R2 产物或算法代码。

使用既有环境中的 Open3D 重读 PLY，并把 R1 清理输入、R2 平面候选、剩余点、彩色聚类投影到同一坐标范围，生成四张审查图。图上是二维投影，可能让不同深度的点重叠；图中的 X/Y/Z 均为未确认单位的原始坐标轴，不代表车辆方向或离地高度。蓝色为 RANSAC 平面候选，灰色为 DBSCAN 噪声，其他颜色为实验性聚类。

数值比较中，平面“方向差”采用两个法向量的**无向夹角**；“平面点集重合度”采用同一 R1 输入点索引的交并比。为了描述碎片化，暂将 **≤30 点**的簇计为小簇。这只是审查用计数界线，不是障碍物尺寸或算法质量阈值。

### 第一批两帧：平面较稳定，聚类明显合并

`sample_000001` 与 `sample_000016` 的 fine/coarse 平面法向仅差 0.3°/0.4°，点集交并比分别为 0.923/0.931。四个平面结果在 X-Z 投影中均集中于第三坐标轴约 2.25 的上方窄带，而原始点云在其下方还有大量结构。**不能据此确定该平面是地面**；结合 R0 所见第一批采集说明标为室内，尤其需要人工核查这片结构的真实语义。

coarse 半径扩大后，两帧的簇数分别由 53→11、54→10，噪声几乎消失，最大簇增至 8,127/7,378 点。对同一 R1 点索引交叉比对，两个 coarse 最大簇都覆盖至少 **4 个** fine 中各有 ≥100 点的簇。图上大面积不同带状/侧向区域也变成同色。这是参数导致多片空间区域被连通的证据，但**不能仅凭二维投影证明它们是多个真实独立物体**。

fine 中分别有 23/53 和 22/54 个小簇；小簇点数仅为 416/11,535 与 423/11,550 个已聚类点。数量碎片化明显，但这些小簇可能是细小结构、扫描稀疏区域或噪声，缺少真值不能将其一律视为误检。

### 第二批 `sample_000001`：法向相近，纳入平面的点变化大

两组平面法向仅差约 0.9°，但平面点集交并比只有 0.583；coarse 比 fine 多纳入 1,405 个点，可能吞入邻近平面或其他结构。fine 的 45 簇中有 34 个 ≤30 点的小簇，且剩余点中 2,097/4,509 为 DBSCAN 噪声；coarse 变为 23 簇和 451/3,104 噪声。较大 eps 将原先分散区域连成更大簇，最大簇的轴对齐包围盒跨度约为 `[13.93, 12.79, 15.86]` 个原始坐标数值；是否合并真实目标无法判断。

### 第二批 `sample_000055`：主平面发生方向切换

fine 的平面法向约 `(0.949, -0.245, -0.197)`，coarse 约 `(-0.055, -0.209, 0.976)`，无向夹角 **78.9°**，平面点集交并比仅 **0.423**。Y-Z 图中 fine 的蓝色点跨越较大的第三坐标值范围，coarse 蓝色点则形成另一条较窄的带状结构。这说明 RANSAC 阈值改变后选中了不同的优势几何面。

fine 有 98 簇，其中 61 个 ≤30 点；coarse 为 44 簇，其中 23 个小簇。coarse 噪声由 3,152 降到 970，最大簇由 1,736 增至 2,673 点。若以后把单个 RANSAC 主平面直接当作“地面”删除，这一帧存在把墙面样或其他非地面大平面整片过滤的明显风险。**现有外参、重力方向和场景真值不足，尚不能判定 fine 平面就是墙，也不能判定 coarse 平面就是地面。**

## 结论与下一步

**RANSAC + DBSCAN 值得保留为离线候选生成和参数敏感性基线，但当前结果不支持继续靠调两项阈值把它直接发展为可靠的地面过滤加独立障碍物检测。** 第一批显示簇合并与碎片化之间的明显权衡，第二批 `sample_000055` 则出现主平面方向切换；这类结构性问题不能从“簇数更少”推导出“效果更好”。

建议先确认坐标单位、零点语义、安装外参与重力/离地参考，再挑选有记录的目标草地、墙面、树木、人员和路障场景，制作少量地面点与障碍物实例真值。届时在同一组标注帧上检查被平面过滤掉的真实障碍点、残余地面点及聚类的拆分/合并情况；同时把现有 Patchwork++ 或局部/多平面地面处理路线纳入对比。DBSCAN 可继续作为候选聚合基线，但应在有真值和物理尺度后再评估参数或密度变化处理。

当前无法从这四帧、二维图和 JSON 判定：哪个平面是真地面、哪些簇是真障碍、fine/coarse 哪组准确率更高，以及最近点数值在车辆坐标系中的距离。这些判断需要标定和逐点/实例真值，而非聚类数量。
