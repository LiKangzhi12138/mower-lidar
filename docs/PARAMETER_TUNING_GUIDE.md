# Mid-360 障碍检测参数配置与效果调优指南

本指南适用于现场 **0.66 m / 前向下俯 7.5°** 的离线基准。先在同一 NPZ 上复测现有配置，再复制配置做单变量对比。不同硬件安装、采样密度和点云单位需要分别验证。[现场配置](../configs/field_66cm_7p5deg_ransac_dbscan.json) · [历史 R3.2 配置](../configs/r3_2_ransac_normal_trial.json)

## 1. 检测流程

1. 读取 NPZ 中的原始传感器 XYZ 与 intensity，保留原输入行索引。
2. 预处理过滤非有限值。现场基准还排除 XYZ 全零的记录。
3. 按安装假设旋转点云，再沿分析坐标 +Z 平移。原始传感器坐标仍用于最近三维距离。
4. 法向约束 RANSAC 寻找地面候选。候选须同时满足角度和绝对竖直截距门限。只剔除通过门限的平面内点。若没有通过的平面，全部有效点进入下一步。
5. Open3D DBSCAN 对保留点聚类。保留点中的低平面可能形成密度可达路径，把相隔的上部点团连成一簇。即使地面已过滤，相邻结构仍可能被较高点连接。
6. 按簇计算中心、轴对齐包围盒、最近三维距离、水平距离和方位，写入 `obstacles.json`。Full 同时输出点云、标记索引和雷达图，便于复核。

高度直接改变平面相对于分析原点的截距，俯角影响坐标变换后的平面法向和截距。本批离线数据使用旧安装参数时 0/111 条接受地面候选，现场参数下 111/111 条通过。这个结果表示几何门限行为，仍需真值确认地面实际分类。[现场回归报告](R3_FIELD_CONFIG_VALIDATION.md) · [输入输出协议](INPUT_OUTPUT_SPEC.md)

## 2. 四个关键参数

以下字段均位于 `configs/field_66cm_7p5deg_ransac_dbscan.json`。正式入口每次运行重新读 JSON，不监听文件变化。每项修改保存后都需用 `--config` 指向实验文件并重新运行。如果以后由在线节点加载，则以该节点实际的配置重载机制为准。

| 参数 | 完整 JSON 路径 | 现场基准 | 单位 | 作用、修改方式及影响 |
| --- | --- | ---: | --- | --- |
| eps | `clustering.params.eps` | 0.35 | 与分析 XYZ 一致的长度单位 | 用正数改变邻域半径。值越大越容易连簇，值越小越易拆分或变成噪声。 |
| min_points | `clustering.params.min_points` | 12 | 点数，正整数 | 设置核心点邻域所需点数。修改后检查稀疏目标、噪声小簇和桥接点。 |
| mount_height | `coordinates.mount_height` | 0.66 | 与 XYZ 一致的长度单位，现场按米假设填写 | 按实测雷达原点对地高度设置。变化会改变分析 Z 与地面截距。 |
| mount_pitch_degrees | `coordinates.mount_pitch_degrees` | +7.5 | 度 | 根据实测姿态和轴向设置。符号由从雷达到分析坐标的旋转约定决定。 |

当前配置保留 `coordinates.unit_confirmed=false`。如果输入经过单位转换，先核对发布链和 NPZ 单位，再重新验证所有长度阈值。只改单位文字不会缩放点云。

## 3. eps

`eps` 是在分析坐标中的三维欧氏邻域半径。DBSCAN 可沿多个近邻核心点把点团连接起来，簇内两端的距离可以大于 `eps`。增大半径会扩大邻域并可能形成连接桥。缩小半径会切断部分连接，也可能让同一实物上的稀疏区失去足够邻居，造成碎簇或噪声。

以 **0.35** 作为对照，可按 **0.35 → 0.30 → 0.25 → 0.20** 逐档测试，固定 `min_points=12`。这些是已有实验的探索值。R3.9 第三包消息 92 的噪声占非地面点比例分别为 **39.57%、46.55%、52.09%、58.09%**。第二包消息 144 的一个 132 点近场结构在 0.20 下分到三个簇，24 点成为噪声。是否对应真实障碍物的过度拆分仍待人工标注。[R3.9 现场诊断](R3_FIELD_MERGING_DIAGNOSTIC.md)

发现合并后，先用 Full 检查地面候选和非地面点，确认低平面是否仍参与连接。再按同一帧小幅降低 `eps`，对照点索引、PLY 和真实场景，检查簇间连接、同一实物拆分与噪声增加。记录目标区域的变化，同时记录全帧统计。

## 4. min_points

正式实现调用 **Open3D** 的 `PointCloud.cluster_dbscan()`。每个点作为邻域查询中心，半径搜索包含中心点自身。邻域达到 `min_points` 时该点成为核心点，非核心点也可能作为边界点被归簇。未归入任何簇的点标为 −1。这个门限用于核心判定，不能根据候选簇数直接判断检测效果。[Open3D 0.19.0 实现](https://github.com/isl-org/Open3D/blob/v0.19.0/cpp/open3d/geometry/PointCloudCluster.cpp) · [项目调用](../scripts/extract_obstacle_candidates.py)

降低门限可让稀疏区域更容易成为核心点，也可能增加小噪声簇或恢复桥接。提高门限可能切断稀疏连接，也可能让远处或稀疏障碍点无法归簇。可探索 **8、12、16、20**，其中 12 是现行基准，其余未做现场验收。固定 `eps`，保留同一批近处和远处目标对比。

## 5. mount_height

项目将其作为从雷达原始坐标原点到参考地面的高度假设，数值沿分析竖直方向加到点坐标。在水平且稳定的场地，以车辆实际作业载荷和姿态测量，记录测量点、地面基准、测量误差及时间。若只能量到外壳底部，应核对外壳参考点到内部坐标原点的偏移。现场 0.66 m 与历史 0.415 m 对应不同安装。

高度错误会偏移地面平面的绝对竖直截距，导致本来角度合格的候选被拒绝。无地面候选时低平面仍参与聚类。现场值应依据测量和外参更新。随意改变高度可能让墙面附近低点或障碍脚部被错误剔除，也会改变分析坐标中的 Z 结果。

## 6. mount_pitch_degrees

物理俯角是雷达相对水平面的前向下俯。当前代码将原始坐标绕 `coordinates.pitch_axis_sensor=[0,1,0]` 右手正转，再沿 `coordinates.vertical_axis_analysis=[0,0,1]` 加高度。这一约定下，前向下俯的校正采用 **+7.5°**。历史 **+5°** 对应另一种安装条件，两者使用同一算法。应核对传感器朝向和水平基准，通过外参确定轴与角度，再按当前符号约定填写。仅凭“下俯”一词改为 −7.5° 会反转变换方向。误差可能令平面法向或截距超限，也会影响水平投影和方位。

## 7. 常见问题

| 现象 | 可能原因与首查项 | 参数方向与副作用 | 复核方法与边界 |
| --- | --- | --- | --- |
| A 多物体连成一簇 | 地面残留或较高点密度桥。先查地面候选和连接路径。 | 先按实测纠正高度/俯角。地面正常后逐档减小 `eps`，可能拆碎单体、增加噪声。 | 用同帧 PLY 和原始点索引对齐实物。遮挡、紧邻目标和真实物体边界须靠额外证据。 |
| B 同一物体分成小簇 | 半径过小、密度不足或遮挡。首看同一实物是否有连续采样。 | 小幅增大 `eps`，或另做降低 `min_points` 的实验。可能增加跨物体连接。 | 同时复核相邻目标和远处点。没有回波的部分无法靠调参补足。 |
| C 地面形成障碍簇 | 安装参数不符、坡度或地面非平面。首查平面诊断及非地面层。 | 高度和角度按实测差值纠正。先保持聚类阈值，观察被剔除点。错误校正可能伤及障碍底部。 | 叠看 `ground.ply`/`nonground.ply` 和真实地面。单平面难覆盖起伏，不宜盲调安装参数。 |
| D 障碍底部被过滤 | 障碍脚点靠近平面距离门限，或拟合平面偏离地面。首查脚点的原始行号和去向。 | 仅在外参错误时改高度/俯角。改变 `eps` 或 `min_points` 无法找回已剔除点。 | 利用低障碍标注核查候选分区。必要时另做地面模型实验，四个参数无法直接改变地面内点规则。 |
| E 稀疏或远距障碍无簇 | 邻居不足。先确认目标是否有有效回波且保留在非地面层。 | 可降低 `min_points` 或独立增大 `eps`，可能引入小噪声簇和误连接。 | 对照多个远近距离的同一目标和近场误报。回波缺失需要检查采集与预处理。 |
| F 噪声点过多 | 半径偏小或核心门限偏高，亦可能是场景稀疏。先看噪声是否覆盖真实目标。 | 单独提高 `eps` 或降低 `min_points`，同时防止背景被聚成簇。 | 比较噪声比例和目标区域覆盖。噪声下降无法单独证明准确率改善。 |
| G 距离或方位偏差 | 单位、轴向或参考原点不同。先分清原始 3D 最近距离与分析坐标的水平量。 | 按实测纠正俯角或高度，校正后需全面复查。聚类阈值仅改变参与统计的簇。 | 用已知位置及方向的标靶验证。单位、偏航、滚转和参考点标定需要单独处理。 |
| H 改 JSON 后效果相同 | 改错文件、使用默认配置、读取旧输出，或新值尚未跨过邻域边界。 | 先显式指定 `--config` 并使用新输出目录。确认实参后再决定是否调整幅度。 | 查看 JSON 的 `coordinate_parameters`、`clustering_parameters`。数值无变化也可能是该帧对参数不敏感。 |
| I 无地面候选 | 法向/截距超限、搜索耗尽、点数不足或退化。先查选中平面字段和被拒绝平面。 | 用测量纠正高度和俯角。不要用放宽聚类条件掩盖全点进入 DBSCAN。 | Core 的空平面字段和 `removed_point_count=0` 表示未接受平面。查看合法去地面样本再复测，输入不足时需检查采集。 |
| J Core 正常但在线效果不同 | 同帧输入、聚合策略、外参、滤波或消费接口不同。先对齐消息 ID/时间戳和点序。 | 先让在线加载相同经核实的配置。随机调聚类参数会掩盖链路差异。 | 逐层比对输入、地面、候选索引和接口字段，再量化在线延迟。在线问题不能从 Windows 离线测试单独归因。 |

## 8. 用 VS Code 复制、编辑和加载配置

从仓库根目录执行。将实测点云放到被忽略的 `data/field/message_000092.npz`，或者调整 `$npz`。实验 JSON 放入 `*.local.json` 可避免误提交。

```powershell
conda activate mower-lidar
$npz = 'data/field/message_000092.npz'
$base = 'configs/field_66cm_7p5deg_ransac_dbscan.json'
$trial = 'configs/field_eps030.local.json'
Copy-Item -LiteralPath $base -Destination $trial
code $trial
```

若 VS Code 的 `code` 命令不在 PATH，直接在 VS Code 中选择“打开文件”。在实验副本中只把 `clustering.params.eps` 改成 `0.30`，保存文件。标准 JSON 使用双引号和小数点，不能写注释、尾逗号、单位后缀或 `+7.5` 这种带前导加号的字面数。角度正值写 `7.5`。可执行 `python -m json.tool $trial` 检查语法。若命令报 `JSONDecodeError`、`KeyError` 或 `ValueError`，按报错行和字段检查语法、层级、类型、算法名及值域。

```powershell
python -B scripts/run_perception.py --input $npz --config $base --mode core --output-dir outputs/tune_base
python -B scripts/run_perception.py --input $npz --config $trial --mode core --output-dir outputs/tune_eps030
python -B scripts/run_perception.py --input $npz --config $trial --mode full --output-dir outputs/tune_eps030_full
Get-Content outputs/tune_eps030/obstacles.json -Raw | ConvertFrom-Json |
  Select-Object coordinate_parameters,clustering_parameters,candidate_count,unclustered_point_count,removed_point_count
```

对照两个 `obstacles.json` 中的配置、点数、尺寸和点索引。必要时对基准也运行 Full，以相同视角检查 PLY。入口要求输出目录为空或尚未创建。确认目标和副作用后，才将已验收变更应用到现场正式配置。

## 10. 现场部署

交付为已验收的离线检测核心。Jetson / ROS 2 集成需要接入真实点云，显式选择符合车辆安装的配置，核实时间戳、单位、轴向和外参，再按协议适配候选及地面诊断。先用录包回放逐帧对照离线结果，再测现场吞吐量、掉帧和端到端延迟。Windows 的离线耗时只适用于对应测试主机与输入。Core 的产物适合部署前回归，Full 用于抽样诊断。[R3.8 性能报告](R3_PERFORMANCE_BENCHMARK.md) · [R3.10 现场验收](R3_FIELD_CONFIG_VALIDATION.md)
