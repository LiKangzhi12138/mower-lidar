# R3.8 性能测量与精简感知模式

测量日期：2026-11-03。本轮已完成先基线、再改流程、再回归与对比；没有修改 RANSAC/DBSCAN 参数、几何公式或坐标语义，没有安装依赖、操作原始 NPZ、提交或推送 Git。R3.7 为此前对话中的只读审查结论。

## 测量方法与数据来源

设备：Intel(R) Core(TM) i7-14650HX，24 个逻辑处理器，物理内存 31.73 GiB；Windows-10-10.0.26200-SP0。已有 Conda mower-lidar / Python 3.11.17；依赖版本见 outputs/r3_performance/environment.json。OpenMP 仍沿用源码的单线程设置。

- 输入仅 sample_000142～000149/lidar/cloud_01.npz；配置固定为 configs/r3_2_ransac_normal_trial.json（0.415、+Y 旋转 +5° 的原实验假设，阈值 0.12、法向 15°、截距 0.2、最多 6 平面，DBSCAN eps=0.35/min_points=12）。不把这些长度数值宣称为最终确认的米值。
- 改动主流程之前，benchmark_perception.py 临时包装原函数测得 baseline_v2：每帧 1 次新进程首帧、1 次预热、20 次有效预热测量。随后冻结 HEAD 337aaa9 的原始 Python 源码到 original_source，与第一次基线记录的主源码 SHA-256 核对一致。补充一致性检查分项后，使用同一旧源码重测 baseline_final2，作为下表原始完整基线。
- 最终对比：baseline_final2（原始完整）、full_final（新完整）、core_final（精简），每组 8×20=160 次预热测量，总计 480 次；每组另有 8 次新进程首帧，各帧只测一次。三组顺序执行，不并发跑基准。临时输出目录独立，R3.2～R3.4 历史产物没有覆盖。
- 墙钟使用 time.perf_counter_ns()，CPU 使用 time.process_time_ns()。函数包装器只增加计时，不改变传入参数和返回值；各阶段在内存中累计，结束后集中记录。NPZ 读包括解压与字段解析，不能当作纯磁盘时间。RANSAC、DBSCAN、候选几何的计时输入均已在内存中，排除了 NPZ 加载阶段，但包括各自需要的 Open3D 对象构造。
- 端到端计时从调用 run_pipeline 前至其返回后，包含配置读取、所有同步输出、校验和 PNG；不含 Python 启动/模块导入、统计输出目录大小和保存测量记录。新进程总时间另测，包含进程启动和依赖导入及测量记录收尾。没有清空 OS 文件缓存，“冷启动”仅指新进程，不指磁盘冷缓存。
- 内存为 GetProcessMemoryInfo 的进程工作集，进入/退出及约每 5 ms 采样；可能漏掉短暂峰值，包含共享库/Matplotlib 缓存，不能当作准确的单帧分配量。CPU 时间可能呈现 Windows 计时粒度。首帧样本少、组间顺序和 OS/存储缓存仍会影响比较；没有实测计时包装/内存采样本身的开销。
- 所有百分位由 NumPy percentile 计算。总体表是八帧等量混合的 160 次分布；逐帧表每行 20 次，P95 仍受小样本限制。嵌套计时（radar_inclusive 包含 png_save）不能重复相加，阶段中位数之和也不等于端到端中位数。

## 实现、兼容性与验收

- scripts/offline_detector.py：run() 增加仅关键字 export_artifacts/context，默认保持原 PLY/NPZ/result.json 导出。core 仍复用同一读取、过滤、坐标变换、normal_constrained_plane、cluster_dbscan、describe_candidate；计算上下文通过引用交给输出层。原始 sensor 用于最近三维距离，analysis_xyz 用于中心/包围盒/水平距离及方位。
- scripts/radar_view.py：抽出共用 _export_context()；独立 export_result() 文件输入接口仍保留哈希、行索引和 PLY 校验；新增 export_memory() 复用同次坐标与标签，只输出 JSON。core 仍保留一次每簇中心一致性检查，未为了降低时间取消几何计算。
- scripts/run_perception.py：--mode full|core，默认 full，旧命令和函数位置参数保持兼容。core 不写 PLY、不复制文件、不重读 NPZ/JSON、不重复哈希、不绘图。
- core 缺失产物的 point_cloud、source_result_json、radar_plot、outputs 中 PNG/PLY 引用为 null，避免虚假文件引用。所有候选数值字段、input_indices、坐标与单位元数据保留。core 携带检测器已有地面模型/计数/拒绝平面/选中平面诊断，不新增 ground_status 或有效性分数。旧的文件依赖检查应使用 full。
- scripts/benchmark_perception.py 为测量包装器；scripts/summarize_performance.py 汇总固定的本次实验目录并核验几何/产物；scripts/check_r3_performance.py 对同一份计算结果分别导出 full/core 并从原 NPZ 重算几何。README、RUNNING_AND_TESTING、INPUT_OUTPUT_SPEC 已更新。
- 同源验收：八帧均通过，同一个 result/context 分别导出两模式，除逐簇文件引用外候选逐字段完全一致；独立重算中心、AABB、原始雷达原点最近距离和分析 XY 最近距离，四方向/原点约定、RGB/坐标 PLY 重读、PNG 解码均通过。
- 480 次预热测量的候选字段在排除 point_cloud 文件引用后逐帧完全相同，每帧每组 20 次中未观察到 RANSAC 结果变动；原始/新 full 第一轮八帧文件清单完全相同，其中 148 个 PLY/PNG 字节一致。八帧历史 R3.4 候选字段也与新 full 完全相同。
- 执行 check_offline_detector.py：7 次真实旧运行、6 类合成边界检查通过；check_r3_radar_view.py 八帧及标准方向检查通过；check_r3_performance.py 八帧同源检查和 core 空点/全零/稀疏无簇检查通过；20 个 Python 脚本语法检查通过；省略 --mode 的正式旧入口及独立 radar_view.py 命令实跑通过。
- 曾出现一次专项测试失败：测试先导入 Open3D，再导入设置 OMP_NUM_THREADS 的共用模块，引起拟合波动；将测试导入顺序对齐正式入口后通过。没有改 RANSAC 算法或参数；最终基准的逐帧候选签名稳定。
- 已知限制：当前没有统一 ground_status/感知有效性协议，本次未擅自定义。core 处理空/全零/无簇输入；full 包装器在候选区域完全为空时仍有原有缺少彩色 PLY 的限制，本轮没有为性能工作改变该行为。

## 运行与复核

```powershell
conda activate mower-lidar
$npz = 'data/historical/sample_000142/lidar/cloud_01.npz'
python -B scripts/run_perception.py --input $npz --output-dir outputs/r3_performance/demo_core --mode core
python -B scripts/run_perception.py --input $npz --output-dir outputs/r3_performance/demo_full --mode full
python -B scripts/check_r3_performance.py
python -B scripts/summarize_performance.py
```

上述两种模式使用相同参数的命令已经实际运行，示例请使用新的空输出目录。重测某组：`python -B scripts/benchmark_perception.py --mode core --output-dir outputs/r3_performance/core_repeat --repeats 20`（也可 full）。baseline 需要保留 original_source 冻结快照；否则测量器拒绝把当前代码当成原始基线。汇总脚本固定读取本报告三组最终目录。

原始记录：outputs/r3_performance/{baseline_final2,full_final,core_final}/measurements.json、metadata.json；聚合为 summary.json，环境为 environment.json，同源验收为 correctness/checks.json。baseline_v2 保存修改前首次完成的基线；baseline_v1/baseline_final 是早期测量器初始化失败目录，不计入统计。所有目录均未覆盖历史结果。

## 尚未验证

已证实 core 在本机显著降低稳态全入口耗时，主要减少静态 PNG 和调试文件链；不是算法精度或车辆实时性结论。没有 Jetson 的 CPU/内存带宽、功耗温度、ROS 2 消息排队/丢帧/时间同步、采集到结果的真实端到端延迟数据；也未证明正式标定或检测准确率。后续应在 Jetson 实机固定输入回放与真实 ROS 2 流中验证 P95/最大延迟、进程内存和持续运行稳定性。
